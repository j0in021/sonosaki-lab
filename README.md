# その先ラボ

「好き」から大学の研究に出会う、高校生向けの小さな探索ツール。
志望校が決まっていない人が、研究の面白さや、大学でやってみたいことに気付く材料を作ります。

## 使い方

1. 最初に候補の数を1〜20件から選ぶ。
2. 作品・日常の興味から「はい／いいえ」で答える。固定20問を廃止し、必要な情報と根拠に応じて質問が変わります。途中で結果を見ることもできます。
3. 異なる3種類の回答根拠がそろった研究室・教員テーマを、希望件数まで読む。不足時は追加質問と不足数を表示します。選択した答えとのつながり、やさしい説明、研究を考える問いの例、確認できた成果、公式出典を表示。
4. 件数の変更、回答の見直し、気になる保存、先生に見せるテキストメモのダウンロード。

回答・保存した候補はブラウザーのlocalStorageだけに保存。ログイン・外部API・解析タグはありません。公式リンクや検索リンクを開くと、その外部サイトへ移動します。

## データと説明の限界

- 東京大学の公式一覧から作成した2,988行のCSVを出発点にしています。研究室・教室・研究分野だけでなく教員単位も含み、表示上も区別します。追加4大学も含めた重複整理後のカタログ2,826件のうち、説明・分野を対応付けられる2,562件が推薦対象です。対象外264件は検査記録で分けています。
- 原本CSVの名前とSHA-256は `site/data/catalog.json` のsourceに保持。各東大レコードは `sourceRowIds` でCSVの物理行へ追跡できます。原本CSV・収集キャッシュは公開リポジトリに含めません。
- 立命館大学のゲーム研究、ASUの科学と想像力、Harvardの小型ロボット、StanfordのVR研究を追加。各行に公式情報源を記録しています。
- 説明には研究分野名を平易に言い換えた文章を含みます。全研究室の現状を個別に監査した一覧ではありません。
- 「たとえば、こんな問い」は入口として編集した例で、当該研究室の実際の進行中プロジェクトを断定するものではありません。
- 成果は原本で確認済みのものだけ表示。未確認を「成果なし」と扱いません。教員が別の所属で紹介された成果を含む場合があります。
- 推薦の3根拠は、テーマ・問い・取り組みの別の回答です。分野から一般的に考えられる取り組みを、その研究室の設備・実施方法の保証には使いません。
- 合格可能性・能力・適性・学校の優劣を判定するツールではありません。配属・授業・募集・入試は公式案内を確認してください。
- 情報確認日：2026-10-28。所属やURLの変更は起こり得ます。

## 推薦の仕組み

全11分野への入口を確認し、未校正の仮定モデルで期待情報量を計算して質問を選びます。異なる3種類の「はい」がそろった候補のみ採用します。等しい事前重み・同点抽選・同一教員の重複除去を使い、全2,562件に到達できる合成回答経路を全件検査しています。全問「いいえ」なら、架空の根拠で候補を作らず0件になります。

**高校生の回答データで校正した統計的最適問数ではありません。** モデルの仮定、終了条件、公平さの定義、検証限界、利用者テスト計画は [METHODOLOGY.md](METHODOLOGY.md) にまとめています。

## ローカル実行・検証

Node.js 22以降とPython 3を使用。外部npm依存なし。

```sh
npm test
npm run check
npm run audit:check
npm run dev
```

`http://127.0.0.1:4173/` で開きます。HTMLをfile://で直接開くとJSON取得ができません。

カタログを再生成する場合のみ、承認された原本を明示して実行：

```sh
python3 scripts/build_catalog.py --csv /absolute/path/to/source.csv
```

## GitHub Pages

`main`へのpush後、GitHub Actionsで検証して`site/`だけをPagesへ公開します。リポジトリSettings → PagesのSourceはGitHub Actionsを選択。Pagesのサブパスでも動く相対パス構成です。

## ファイル構成

- `site/` 公開される静的アプリと出典付きデータ
- `scripts/build_catalog.py` 原本から公開データを作る処理
- `scripts/build_questions.py` 47分野それぞれの3種類の質問を生成
- `scripts/audit-reachability.mjs` 全候補の合法な到達経路と3根拠を検証
- `scripts/check-site.mjs` 構文・ローカル資産・URLの検証
- `tests/engine.test.mjs` 分岐・正確な件数・不正入力・全問いいえなどのテスト
- `METHODOLOGY.md` 情報量・終了条件・公平さ・統計的な検証限界
- `site/data/reachability-audit.json` 全候補の合成検査記録（実利用者データではありません）
- `REQUIREMENTS.md` 目的・対象・機能・データ・受入条件をまとめた要件定義書
- `.github/workflows/pages.yml` 検証とデプロイ

画面と説明はこのプロジェクト用に作成。作品名は関心の例として使用し、画像・ロゴ・キャラクターは使用していません。大学公式のサービスではありません。出典サイトの権利は各権利者に帰属します。
