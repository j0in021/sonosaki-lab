# 個別研究の確認手順

1. `data/individual-review-queue.csv`のpending IDを選ぶ。元行・公式URL・不足理由を読む。
2. 公式の研究紹介を開き、そのIDの教員／研究室であることを確認する。同姓・同じ分野名で別人物を混ぜない。
3. 対象・具体的な問い・作業／方法の3内容を特定する。研究室名から推測しない。資料にない活動は追加しない。
4. 内容を高校生向けに言い換えた質問、短い導入、簡単な追加説明を作る。同じ関心を3回言い換えない。
5. `data/evidence-ledger.json`へ質問と対応説明、URL、該当見出し、確認日を記入する。必要情報がなければpendingのまま、取得結果と次に必要な資料を `data/review-observations.json`へ記録する。
6. `python3 scripts/build_catalog.py --csv <既存原本CSV>`、`npm run questions`、`python3 scripts/review-queue.py`、`npm run audit`で生成する。原本の別コピーを作らない。
7. 正しい内容から到達する正例と、同語の別意味・隣接分野から誤って推薦しない負例を確認。`npm test`、`npm run check`、`npm run audit:check`を実行する。
8. `npm run release:check`が失敗する間はpush・Pages公開を行わない。全件通過後も内容レビューと画面検証をしてから公開し、配信資産を照合する。

現時点の未確認は作業の残りであり、研究が存在しない／成果がないという意味ではない。データを減らしたり、URL疎通だけでverifiedにしたりして公開条件を満たしてはならない。

## 100件ずつの並行確認（2026-10-29追加）

本人の指定により、未確認2,778件を100件ずつ（最後のみ78件）、28組に分割した。[分担表](../data/review-batches/manifest.json)のIDと入力hashを固定し、同じレコードの二重担当を防ぐ。最初の3組を3サブエージェントへ割り当て、親エージェントは統合と再照合を行う。

各担当者の書込み先は自分の `batch-NNN.results.json` と `batch-NNN.report.md` のみ。中央の根拠台帳・生成物を直接変更しない。10件程度ごとに途中保存する。100件担当したこと、100件調査を終えたこと、100件の根拠が確認できたことは別々に数える。

結果には中央台帳と同じ形式の `entries`、不足を記す `observations`、実際に読んだURLと個別判断を記す `outcomes` を含める。`outcomes` は `verified` または `needs-more-evidence`。対象・問い・方法を個別資料で裏付けられなければ確認済みにしない。

```sh
python3 scripts/check-review-batch.py batch-001
python3 scripts/check-review-batch.py batch-001 --require-complete
```

この検査は担当IDの一致、重複、記録漏れ、根拠形式を調べる。資料の意味や質問の適切さを自動認定せず、中央台帳への統合も行わない。親は出典と個別対応を再照合し、疑義があれば担当へ差し戻す。統合済みの内容だけを既存の確認済み件数へ加算する。未確認・取得不能・再照合待ちを合格へ置き換えない。全件の個別確認と受入検査が終わるまで公開しない。

### 担当間の独立レビュー

元の個別調査を終えた担当は別組の草案を公式資料と再照合する。最初に016と022を相互に割り当てた。対象・問い・方法が同じ研究例につながるか、所属、成果と計画、平易な説明を各IDで確認する。入力snapshotのhash、実際に読んだ出典、各IDの採否と理由を記録し、合格した修正後entryを返す。中央台帳への書込は親のみが行う。[独立レビュー分担表](../data/review-batches/cross-review-manifest.json)で追跡する。

### 別チャットとサブエージェントの併用

本人の追加指定により、各別チャットが最大3サブエージェントへ未確認IDを重複なく分担し、チャット本体がその組の結果を取りまとめる。自分の一次調査を自分で独立レビューした扱いにはしない。中央の全28組の独立レビュー分担表に従い、調査後に別組を確認する。親は差戻し・統合・アプリ検証を担当する。起動指示と実際の稼働・調査完了は区別する。

## 再発防止の受入条件（2026-10-29）

追加・変更時は[根本原因と全件対策](ROOT_CAUSE_AND_PREVENTION.md)の5項目を各IDで確認する。研究者名だけの一致、同一URLだけの一致、3つのfacet名だけの一致では受け入れない。隣接組織・兼担・別研究の混入や時制に疑義があれば保留する。独立レビューは入力hashを固定し、修正後の本文を照合する。中央統合後は `npm test` と `npm run content:check` を実行する。未確認は推薦しないという現行方針を維持する。

## 承認本文の固定

`data/review-approvals.json` は確認済み本文のSHA-256を保持する。既存161件の初期値は既存台帳から移行したもので、新しい独立レビューの証拠ではない。新規・変更時は内容レビューを終えた版に対し、承認者・確認日・判断記録の参照を残してから対応する承認を更新する。ハッシュだけを自動更新して検査を通してはいけない。ハッシュはUTF-8の `json.dumps(entry, ensure_ascii=False, sort_keys=True, separators=(',', ':'))` に対して計算する。本文変更は質問再生成・全件検査を必要とする。
