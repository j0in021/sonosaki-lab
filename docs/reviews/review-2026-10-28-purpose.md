# 独立レビュー③：進路探索という目的に対する方法の妥当性

対象：その先ラボ / `f268d0123e9a6595ed953ef80bf6d851b4971038` / 2026-10-28

レビュー担当：purpose_review。ほかの担当の報告を読まず、現行コード、要件定義、方法論と一次資料を照合した。コード・データ・公開サイトは変更していない。

## 判定

**現行方式を、この目的に最適な方法とは判断できない。さらに、単なる「最適性未検証」より手前に、対象利用者と仕組みの具体的な不整合がある。** 現行方式は、すでに表明できる関心をタグ集合に当てはめて候補を絞る試作としては合理的な要素がある。一方、目的は「まだ何をしたいか分からない高校生が、知らなかった研究を知って興味を育てる」ことも含む。関心の推定と関心の形成は同じ目的関数ではない。

yes/no、可変質問、出典表示、根拠の捏造を避ける条件、同点抽選、本人が止められる操作は維持する価値がある。改善の中心は質問数だけの増減ではなく、**研究例を知る → 理解を確かめる → 関心を答える → 別の可能性も比べる**という循環である。これは有望な仮説であり、効果の実証結果ではない。

重大度：P0=直ちに停止を要する問題、P1=対象の中核利用に支障があるため優先設計修正、P2=品質改善または実証が必要、P3=小改善。本レビューはP1 2件、P2 3件。法令・適性検査としての認証などは評価範囲外。

## 指摘

### P1-1：関心がまだ薄い人ほど、長い質問列の末に研究例を得られない

- **観測**：`site/engine.js:58`は3種類の肯定回答がそろわないレコードを推薦から除く。`site/engine.js:69-70`では希望件数がそろわなければ情報利得が小さくても自動終了せず、最後の質問まで進み得る。`site/app.js:156-164`の0件時は回答見直し・追加質問・一般的な次の行動が中心で、研究を知って回答し直すための具体例は表示されない。
- **再現**：希望5件、質問seed=123、推薦seed=456。全noは155問・0件。さらに、全11入口と全47テーマ関心にはyes、問い・活動・物語にはnoという合成利用者は、**58個のyesがあっても155問・0件**になる。実在の高校生の発生率を示すものではないが、正規の回答経路で成立する。
- **目的上の影響（推論）**：「分野は気になるが、大学での調べ方までは想像できない」という入口段階の利用者に、研究を理解する材料を与える前に研究活動への意思表示を要求している。3根拠の要件を守るために個別推薦を0件とすること自体は正直だが、そこで教育的な価値も0件に近づける必要はない。
- **改善**：3根拠未満のものを推薦として水増しせず、質問の前後に短い出典付きの研究事例を教材として見せる。yesが少ない経路では「例を見てから、もう少し考えてみる？」というyes/noの分岐を置く。候補N件の枠は根拠付き推薦専用のまま維持する。資料を見た後に意味の異なる3根拠を確認する。155問まで自動で続ける前に、本人が探索方法を変える機会を作る。
- **受入検査案**：全no・テーマだけyesの経路でも、追加の肯定を強制せず、具体的な研究を理解する教材と明確な区切りへ到達できること。試験参加者が「0件だから大学研究に向いていない」と解釈しないかを確認する。

### P1-2：「知らない／判断材料がない」と「今は関心がない」が同じnoとして推定に入る

- **観測**：`scripts/build_questions.py:76-78`は、分野名への関心、特定の問い、特定の取り組みを直接聞く。`site/app.js:119-120`はnoを「今はそうでもない」と表示する。`site/engine.js:43-44`では、すべての有効回答を同じ0.75/0.25モデルで尤度へ反映する。質問内容を理解できたかや、初めて聞いたかを保持する状態はない。
- **具体例**：「『分子・化学反応』の話題に、つい目が向く？」「物質の組み合わせや反応を比べ、新しい分子を作る方法を考えたい？」。経験・語彙がまだない人も回答しなければならない。「詳しくなくても大丈夫」という注記は心理的な助けになるが、回答の意味をデータ上で区別しない。
- **影響（推論）**：未知ゆえのnoを嗜好の反証として累積すると、未知の研究を知るという目的と衝突する。「いいえは向いていないという意味ではない」というUIの説明は適切だが、内部の関心推定の曖昧さを解消しない。
- **改善**：第三の選択肢を足さず、必要な場面だけ「何をする研究か、イメージできた？」→noなら説明→「これなら少し気になる？」の二択を分ける。理解確認のnoは嗜好スコアに入れない。昔のnoも恒久除外せず、新しい例を見た後の回答として更新可能にする。
- **受入検査案**：「未理解no」と「理解後の関心no」を区別して保持・再生できること。認知インタビューでnoを選んだ理由を観察し、誤分類の頻度を調べる。追加確認の負担も同時に評価する。

### P2-1：情報利得は「興味が育った」「研究を理解した」の代替指標になっていない

- **観測**：`site/engine.js:52-55, 83-97`の選択目標はタグ仮説の不確実性減少と欠けたfacetの獲得。`site/engine.js:70`の終了条件にも、新しく理解した研究、納得して保存できる候補、疲労は入らない。`METHODOLOGY.md:104-114`に実利用者評価は今後の作業と明記されている。
- **影響（推論）**：関心が広い人は本来複数分野を探索してよいのに、モデルは一つの既存タグ集合を潜在仮説として絞る。出典紹介によって関心が変化する過程もモデル化されない。情報量が下がったことは学習完了や進路判断の十分性ではない。
- **根拠**：参考に挙げられたDewの研究は衣服などの選好を効率的に測る方式であり、高校生の興味形成を検証したものではない［S4］。Hidi・Renningerは関心が状況的なきっかけから発達し得る枠組みを提示する［S1］。後者の枠組みも、このUIの有効性の直接証明ではない。
- **改善**：情報利得は候補質問の補助順位として残し、主な成功指標を「初めて知った研究の内容を説明できる」「気になる理由を自分の言葉で言える」「次に見る資料を一つ選べる」にする。質問上限や終了閾値は、その成果と負担の比較から採択する。
- **判定**：実装が宣言済みの数式を違反しているという指摘ではなく、最適化対象がプロダクト目的を十分に表していないという設計指摘。

### P2-2：全候補への到達可能性と、一人が見る選択肢の幅は別物

- **観測**：`site/engine.js:118-128`は個別関連度順＋同点抽選、同じ研究者の重複除去である。選ばれたN件の分野・問い・アプローチの重なりを抑える処理はない。質問seed=123、推薦seed=456、全yes、希望5件では25問で終了し、田近英一・野田祐作・小宮剛・黒川宏之・宮本研究室が選ばれた。5件のタグはいずれもearthまたはspaceを含む。全yesを一般的な生徒と想定してはいないが、広い肯定から幅広い候補が必ず得られる設計ではないことを示す。
- **影響（推論）**：全件到達監査が成功しても、利用者が大学研究の幅を知れるとは限らない。学校を決めていない人には、同系統の候補が多数並ぶより異なる研究の比較が有益な場合がある。ただし、その好みには個人差がある。
- **改善**：「近い研究を詳しく比べたい？」をyes/noで聞き、noなら、3根拠がある候補の範囲で問い・分野の異なりを考慮した並べ替えを比較実験する。N件の中に根拠のない候補を勝手に混ぜない。候補ごとの到達可能性・同条件抽選の監査も維持し、導入した多様性制約が一部の候補を恒久的に除外しないことを再検査する。
- **根拠と限界**：音楽推薦のAuralistは正確さだけでなく多様性・新規性・偶然の発見を組み合わせて評価している［S5］。音楽分野の結果は、高校生の研究探索へ直接転用できない。「多様性を最大化すれば最適」とは判断しない。

### P2-3：段階的な発見の設計が、主に一つの物語経路に限られる

- **観測**：`scripts/build_questions.py:71-73`に3問の物語経路があり、`site/engine.js:75-80`がculture→呪術→歴史→伝承の順を優先する。他の47テーマは各3問を効用順に選ぶため、関心→問い→取り組みの順は保証されない。技術関心の合成経路では11入口後に `topic_software_activity` → `topic_software_inquiry` → `topic_software_interest` の順となった。
- **影響（推論）**：趣味を足場に研究の具体像を知るという中心体験が、多くの分野では分類質問の連続になる。活動から聞くこと自体が必ず悪いわけではないが、難度や前提理解を管理するルールがない。
- **改善**：全分野を同じ一律の3問順に固定する必要はない。たとえばゲームの「遊ぶ・作る・社会への影響」、食べ物の「味・安全・生産」、スポーツの「体・道具・チーム」のように、日常の具体例から複数の学問へつながる小さな学習経路を作る。一次資料と結び付け、利用者が内容を想像できてから活動の質問を出す。
- **保持すべき点**：先生向けメモと次の行動は良い。`site/app.js:163`と`site/engine.js:146`は対話・公開講座・公式情報へつなげる。ただし、現状は提案した段階であり、対話が実施されて進路理解が進んだとは確認されていない。進路についての対話と後年の就業成果の関連を示すOECD資料は、この導線を検討する根拠にはなるが、アプリの因果効果を証明しない［S3］。

| 方式 | 利点 | 主な欠点・必要検証 | 推奨扱い |

| 現行：情報利得＋3facet | 実装が単純で合法経路を検証しやすい。根拠を水増ししない | 未理解と無関心の混同、教育内容不足、0件の長い経路 | 比較用ベースラインとして残す |

入口教材は推薦結果とは別に明示し、研究室数を選ぶ機能や3根拠の要件を黙って緩めない。「分かった？」「気になる？」「続ける？」はすべてyes/noで表現できる。

## 現実的な検証計画

1. **意味・理解の検査**：進路未定、関心がある、専門語に慣れていない等の背景を含め、まず少人数で質問を声に出して説明してもらう。初回8〜12人程度は不具合発見用の運用案であり、統計的な最適サンプル数ではない。noの理由と、表示根拠を誤って実績保証と読まないかを観察する。質問・教材の内容は専門家も確認する。
2. **目的指標を先に定義**：主指標は「初めて知った研究を一つ、内容と気になる理由を説明できる割合」。評価者が条件を知らない状態で短い回答を基準に採点する。副指標は根拠の納得、知らなかった分野数、次の行動の選択、完了・自発中断、時間、負担感。保存クリックだけを興味形成の達成としない。
3. **同条件の比較**：現行と教材付き方式を無作為割付し、同じカタログ、同じN、同じ3根拠条件にする。進路未定度・学年・既知の関心の強さを事前に記録する。多様性制約は別の実験で追加し、複数の変更の効果を混ぜない。
4. **質問数の決め方**：得たい改善幅と負担増の許容範囲を先に決め、予備データから必要人数を設計する。学習用と評価用の参加者を分けて、終了条件・理解確認頻度を比較する。一つの固定問数を最適値とするより、成果と負担の条件を満たす可変方針を評価する。現在の0.75・0.15・0.01を正解ラベルにしない。
5. **短い追跡**：同意を得た参加者に、後日、公式資料を見たか・先生や家族と話したか・気になる理由が残っているかを確認する。大学受験への関心が高まったかと、出願・成績への長期効果を分ける。
6. **収集方法**：現行の無送信設計を守り、公開サイトに無断で解析を追加しない。試験参加への説明・必要な同意を整えた別の評価セッションで集める。人数・属性が不十分な段階では「すべての高校生で最適」と結論しない。

回答数だけから離脱率・疲労・不満を推定してはいけない。長さの効果には調査形式や対象による差があり、Sandelinの住民調査実験では長い票の影響が紙回答とweb回答で異なり、webの回答率差やデータ品質の悪化は検出されなかった［S6］。本レビューの155問への懸念は実装経路と目的からのリスク判断で、当該製品の実測結果ではない。
