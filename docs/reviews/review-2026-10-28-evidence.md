# 独立レビュー①：質問は研究室推薦の根拠になるか

対象：`f268d0123e9a6595ed953ef80bf6d851b4971038` / 調査日：2026-10-28（JST）

担当：evidence_review。実装・データは変更せず、この報告のみ作成。他担当の報告は参照していない。

## 判定

**現状の「3種類の回答がある」は確認できるが、「その研究室を薦める実質的な根拠が3つある」は成立しない例がある。要修正。**

回答の捏造はしていない。趣味の入口を数えず、異なる質問IDと3種類のラベルを要求する実装もある。しかし、研究室への対応は共通タグの一致だけで決まり、質問が尋ねた具体的な問い・活動を、その研究室の出典が裏付けるかを検証していない。誤分類されたタグ1個が、形式上の根拠3個へ増幅される。

確実な問題2件（P1×2）と設計上の懸念1件（P2）を報告する。P0なし。下記は目的抽出した反例であり、全2,562件の誤分類率を示さない。

## E1 — P1 / 確実な不具合：同じ単語の別の意味を同一分野と扱い、無関係な3根拠が成立する

## E2 — P1 / 確実な不具合：大分類が正しくても、具体的な問い・活動の根拠にはならない

該当：`scripts/build_questions.py:74-78`、`site/engine.js:34-36`、`site/app.js:138`。データは`site/data/catalog.json`（1行JSON、以下のIDで特定）。

例：`utokyo-c38bfde32a4e` 溜箭将之先生は、[公式紹介](https://www.j.u-tokyo.ac.jp/faculty/tamaruya_masayuki/)にスポーツ法があり、スポーツという入口自体は誤りではない。しかし現在は次の3回答を理由に表示する。

1. 「スポーツ・体の動き」の話題に、つい目が向く？
2. 上手な人の動きには、どんな秘密がある？ 調べてみたい？
3. 体の動きを比べ、上達や安全につながる手がかりを探したい？

公式に示された法学領域は、2と3の身体動作・技能向上を裏付けない。合法24回答、希望件数を20へ変更、推薦seed=0で9位に実表示されることをエンジン上で再現した。誤分類を直すだけでは、この大分類→具体課題への飛躍は残る。

`reasonsFor`は問い・活動ごとの出典を持たず、3理由すべてに`lab.sources.description || lab.sources.directory[0]`を付与する。コードが検査するのはタグとURLの存在であり、そのURLが具体的な回答との関係を示すかではない。

F14の「問い・取り組みは例であり実施課題を保証しない」という注記は適切な限定だが、**その例への回答を研究室固有の推薦根拠にする妥当性までは作らない**。例としての紹介と、推薦の証拠という二つの用途が混在している。

修正案：研究室ごとに確認済みの「対象」「具体的な問い」「活動・方法」の対応を保存し、各対応に根拠箇所とURLを付ける。例えばスポーツ法には「競技のルールや選手の権利を考えたい？」などの確認を経る。分野レベルしか確認できない場合は「この分野を知る入口」と明示し、3つの研究室固有根拠がある扱いを避ける。分野共通の問いを使う場合も、個別研究への対応を人が確認する。

## E3 — P2 / 設計上の懸念：問いと活動がほぼ同じ関心を聞き直す例がある

該当：`site/question-bank.js:3863-3918`、生成元`site/data/topics.json:430-441`と`scripts/build_questions.py:44,76-78`。要件F09は`REQUIREMENTS.md:31`。

統計の2問は次の通り。

- 問い：「たまたま起きたことと、本当の関係はどう見分ける？ 調べてみたい？」
- 活動：「データに見える関係が偶然かどうか、確かめる方法を考えたい？」

質問IDとfacetは異なるが、どちらも偶然と関係を区別することへの関心を聞いている。量子・エネルギーにも、問いの目的に「調べる／比べる」を足して活動にする例がある。文面の違いがあるので「同じ回答を機械的にコピーした」とは言えないが、異なる推薦理由が一つ増えたと判定する内容妥当性は弱い。F09の意味的な受入条件が未実装である。

また`site/engine.js:19,44`は同じタグへの回答を、facet別の意味を区別せず繰り返し尤度へ乗算する。同じタグの3つのyesだけなら、該当/非該当プロファイルの尤度比は仮定上3^3=27倍になる。実際に27倍の証拠が得られたことを示すものではない。METHODOLOGY.mdは条件付き独立の単純化と未校正を明記しており、「測定済みの信頼度を偽称した」という指摘ではない。

修正案：「対象への関心」「解きたい具体的問題」「やってみたい作業」を内容上区別し、同じ課題の言い換えを重複根拠に数えない。活動質問には例えば比較する資料・集めるデータ・作るものを具体化し、その研究室の確認済み活動へ接続する。質問ペアの意味の重複を専門家レビューし、実際の高校生の理解・回答相関も検証する。単にIDを3つに増やして解決しない。

## 成立している点・検証の限界

- `buildProfile`はyes回答だけを記録し、`reasonsFor`はtopic段階だけを根拠にする。無回答やnoをyesに変える捏造は今回確認していない。
- 3facetが揃わない候補を推薦しないゲートはある。この形式検査自体は意味がある。
- 比較として[Harvard Microrobotics Lab公式研究紹介](https://www.micro.seas.harvard.edu/research)も確認した。生物に着想を得たロボット・駆動・制御への質問は、この研究室への探索入口として合理的に対応する。ただし、全候補が同じ水準で裏付けられた証拠にはならない。
- 既存の全件到達検査（`scripts/audit-reachability.mjs:18-26`）は、対象タグに一致する質問へyesと答え、同じタグで採否を判定する。到達可能性の検査としては成立するが、タグの正しさや質問の意味的な対応を独立には検査しない。
- 既存テスト（`tests/engine.test.mjs:15-26,40-43`）もID・facet・タグ・URL形式の検査であり、ここで示した反例を検出できない。
- 目的抽出した経済・植物学・触覚工学・法学・社会学・ロボット工学を一次資料と照合した。全2,562件の個別監査、実生徒での理解・心理測定、ブラウザー描画の再検査はこのレビューでは実施していない。立命館ゲーム研究センターの直接取得はタイムアウトし、今回の判定根拠に用いていない。

## 総合担当への提言

まずE1の語義誤分類とE2の根拠の対応付けを是正し、その後E3の質問内容を見直す。質問数の調整や到達率の再監査だけを先にしても、「誤った理由で到達できる」状態は解消しない。正式な受入判定には、到達可能性とは別の意味的根拠台帳と、正例・負例を含む確認が必要。
