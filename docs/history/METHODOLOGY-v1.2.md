# 質問数・推薦根拠・公平さの設計

版：1.2 / 2026-10-28

## 結論と検証の範囲

以前の20問は短時間で試せるように決めた設計値で、統計的な最適問数ではなかった。この固定数は廃止する。

現在は、全11分野の入口を確認し、候補ごとに3種類の回答根拠を確保したうえで、追加質問の期待情報量が低くなるまで質問を選ぶ。途中で現在の結果を見ることもできる。これは仮定モデルに基づく適応探索であり、高校生の実測回答で校正した最適質問数・適性検査・心理尺度ではない。

最小必要根拠数3はユーザー要件であり、統計的有意性や95%の信頼度を意味しない。異なる3つの回答も、統計的に独立だとは主張しない。

## 研究上の参考

- Ryan Dew, *Adaptive Preference Measurement with Unstructured Data*, Management Science（2024オンライン公開、2025巻号掲載）。不確実性と情報量をもとに、選好を尋ねる質問を適応的に選ぶ研究。https://doi.org/10.1287/mnsc.2023.03775
- Choi et al., *A New Stopping Rule for Computerized Adaptive Testing*。追加項目の予測される精度改善に基づく終了ルールを検討。https://pmc.ncbi.nlm.nih.gov/articles/PMC3028267/

これらは「このアプリには何問が最適か」を検証した論文ではない。このアプリは論文のIRT尺度や校正済みパラメータを移植したものでもない。

## 1. 質問の構成

- 広い入口11問：人文、表現、心・学び、社会、街・空間、自然、生命、物質、宇宙・物理、数理、技術。
- 話題からの寄り道3問：作品→呪術の歴史→伝承の聞き取り。
- 47分野 × 3種類 = 141問：テーマへの関心、具体的に知りたい問い、やってみたい取り組み。
- 質問バンク合計155問。ただし、155問すべてを通常必須にする設計ではない。必要な質問だけ選び、途中でも結果を見られる。

趣味の入口や大まかな分野への「はい」だけでは、推薦の3根拠として数えない。具体的な分野に対する3種類の質問が必要。

## 2. 仮定モデル

各研究テーマの分野タグ集合を、仮の関心対象を表す仮説として扱う。初期の重みは推薦対象レコードごとに等しい。大学名、教員名、CSV順、分野タグの出現回数は加点しない。タグが同じ566組は同じ計算を共有するが、各レコードの初期重みを消さない。

質問の分野と仮説の分野が重なる場合の「はい」の確率を0.75、重ならない場合を0.25と仮定する。「いいえ」はその補数。回答ごとに尤度を掛け、対数で計算する。

**0.75は実測した回答の一貫性ではなく、試作モデルの仮定。** 複数の関心を一つの分野集合で近似し、質問への回答を仮説に条件付けて独立に扱う単純化がある。相関する質問、迷い、解釈の違い、回答疲れを十分にモデル化していない。

## 3. 次の質問

質問qで「はい」と答える予測確率をpとすると、期待情報量は次の式で求める。

```text
H(p) = -p log2(p) - (1-p) log2(1-p)
期待情報量 I(q) = H(P(はい | 回答履歴)) - H(0.75)
```

- 全11分野の入口を確認する制約を先に満たす。
- 呪術などの寄り道は、直前の関心に応じて自然につなげる。
- その後は期待情報量を主に使い、推薦に足りない種類の根拠を得られる見込みも加味する。
- 根拠不足時の補助効用は `期待情報量 + 0.15 × 欠けた種類を補える仮説の重み`。
- 同じ効用の質問は、セッションの乱数で順を決める。質問順と候補抽選には独立したseedを使い、質問順に条件付けたときにも候補抽選を固定順にしない。

これは制約付きの貪欲な質問選択であり、全質問列を比較した大域最適解ではない。

## 4. 終了

通常の自動終了には、次のすべてを要求する。

1. 全11分野の入口を確認した。
2. 3種類の回答根拠がそろった候補が、希望件数以上ある（同一教員の重複を除く）。
3. 残る質問の最大期待情報量が0.01 bit以下になった。

質問バンクを使い切った場合も終了する。モデル上の区切りに達しても、利用者が「ほかの入口も、もう少し探す」を選べば、未回答の質問を続けられる。0.01 bitは実測で最適化した値ではなく、未校正の運用しきい値。途中の結果表示は利用者自身の区切りであり、統計的な終了基準を達成したという表示にはしない。

全問「いいえ」の場合、個別推薦は0件となる。理由を発明したり、無関係な候補で希望件数を埋めたりしない。必要なら途中の確認状況で区切り、別の入口や進路相談へ進める。

## 5. 推薦理由

各候補に次の3種類を1つずつ示す。

| 種類 | 必要な証拠 |
| --- | --- |
| 気になるテーマ | 当該候補の掲載分野に対応する、テーマ質問への「はい」 |
| 知りたい問い | 当該候補の掲載分野に対応する、問い質問への「はい」 |
| やってみたい取り組み | 当該候補の掲載分野に対応する、取り組み質問への「はい」 |

3つの異なる質問IDと3つの種類、対応分野、分野の出典URLを検査する。「いいえ」、趣味の質問、汎用の方法の推測、同じ回答の言い換えを根拠として水増ししない。

問い・取り組みは研究分野を理解する例であり、研究室がその方法や課題を現在実施しているという証明ではない。成果の出典とは別に扱う。

## 6. 公平さ

公平さの保証対象を明確にする。

- 推薦対象2,562件すべてに、適法な質問経路から3種類の根拠を得て、最上位同点候補へ到達し、実際に先頭へ選ばれる回答例・抽選seedがあること。
- 各候補の事前重みと採用条件が同じであること。
- 同じ回答との対応を持つ同点候補は抽選し、固定のCSV順・ID順・大学順で一部だけが常に出ないこと。
- 同一教員の重複は抽選・関連度の順序を決めた後に除き、ある所属レコードだけを永久に排除しないこと。

**異なる興味の利用者に、関連度を無視して全研究室を同じ回数表示するという意味ではない。** 実際の公開サイト全体で表示回数が均等になったかは測定していない。現状は利用者データも表示履歴もサーバーへ送信しない。

元カタログにあるが説明・タグ・URL等の確認が足りず対象にできない264件は、到達可能と偽らず監査記録に分ける。全2,826レコードを確認済み推薦対象と呼ばない。

## 7. 全件検査

`npm run audit` で `site/data/reachability-audit.json` を生成する。

- 566種類のタグ集合ごとに、実際の次質問選択を使って合法な合成回答経路を作る。
- 各対象の分野と重なる質問に「はい」、ほかに「いいえ」と答える。
- 全11分野確認と3種類の根拠がそろった時点で、対象が最高尤度の同点候補集合に含まれることを確認する。この時点は画面の「いまの結果を見る」から利用可能。
- 2,562件の各IDに、質問経路・3根拠の質問ID・分野の種類・同点集合の大きさを対応させる。独立の候補抽選seedを探し、実際の推薦関数から当該IDが先頭へ選ばれることも全件確認する。
- 20件の同条件候補から先頭を選ぶ合成試行を20,000回行い、固定順で偏っていないかを実装検査する。これは実際の高校生のデータではない。
- エンジン・質問バンク・カタログのSHA-256を保存する。CIでは `npm run audit:check` により再計算と比較し、古い監査記録を使わない。

## 8. 統計的な最適問数を決めるために残る作業

実際の高校生を対象に、説明と同意を整えた利用者テストが必要。現在の利用者の回答を無断収集する変更は行わない。

- 事前に目的指標を決める：本人が関心を持てた候補、知らなかった分野の発見、回答負担、途中離脱など。
- 分野の偏り、回答傾向、質問間の相関を調べ、回答モデルを校正する。
- 質問選択・0.75・0.15・0.01の設定を、学習用と独立した評価用の利用者で比較する。
- 推薦への納得と負担の兼ね合いを評価し、しきい値と終了条件を採択する。
- 専攻が少ない分野や、特定の作品を知らない人にも到達機会があるかを点検する。

これが済むまでは「統計的に最適な○問」「95%の精度であなたに合う」などとは表示しない。
